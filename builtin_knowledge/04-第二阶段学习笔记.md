## ① LangChain 是什么？

### 一句话
> **AI 开发的"标准工具箱"。** 别人把 RAG、Agent、工具调用这些都封装好了，你不用自己手写 Embedding/FAISS 那一套。

### 为啥要用 LangChain？
```
没有 LangChain 时（咱们现在的项目）：
    自己写 DocumentChunker      → 100行
    自己调 SentenceTransformer  → 50行
    自己写 FAISS 检索            → 50行
    自己组装 Prompt              → 30行
    自己管理会话                 → 30行
    共计：260 行

有 LangChain 时：
    from langchain import ...
    10 行搞定
```

### LangChain 的核心组件

| 组件 | 作用 | 类比 |
|:---|:---|:---|
| **Document Loaders** | 读取各种格式文件 | 开瓶器——PDF、Word、网页都能读 |
| **Text Splitters** | 文档切分 | 咱们的 DocumentChunker |
| **Embeddings** | 向量化 | 咱们的 SentenceTransformer |
| **Vector Stores** | 向量数据库 | 咱们的 FAISS |
| **Chains** | 把多个步骤串起来 | 流水线——输入→检索→生成→输出 |
| **Agents** | 智能体 | 能自己决定调用什么工具 |

### 对比：用 LangChain 写 RAG

```python
# 咱们现在手写的版本（rag_engine.py ~200行）
# ──────────────────────────────
# 要自己处理：切分、转向量、建索引、检索、组装 Prompt、调 API

# 用 LangChain 的版本（~20行） 🚀
# ──────────────────────────────
from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import MarkdownHeaderTextSplitter
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS
from langchain.chains import RetrievalQA
from langchain_openai import ChatOpenAI

loader = TextLoader("笔记.md")
docs = loader.load()

splitter = MarkdownHeaderTextSplitter([("##", "章节")])
chunks = splitter.split_text(docs[0].page_content)

embeddings = HuggingFaceEmbeddings(model_name="paraphrase-multilingual-MiniLM-L12-v2")
vectorstore = FAISS.from_documents(chunks, embeddings)

llm = ChatOpenAI(model="deepseek-v4-flash-free", base_url="...", api_key="...")
qa_chain = RetrievalQA.from_chain_type(llm=llm, retriever=vectorstore.as_retriever())

answer = qa_chain.invoke("什么是 Token？")
```

## ② LangGraph（LangChain 进化版）

### 一句话
> **把 AI 流程画成"流程图"来执行。** 每一步做什么、走哪条分支，都画清楚。

### LangChain vs LangGraph

```
LangChain：     A → B → C → D（直线流水线）
LangGraph：     A → B → (条件判断) → C 或 D → E
                     ↑                    │
                     └──── 循环回到 B ────┘
```

### 典型场景：Agent 的思考循环

```
用户问："帮我查北京明天天气，然后安排一个行程"

用 LangChain（直线，做不到）：
    一次调用 → 返回结果（没法"先查天气再规划"）

用 LangGraph（有循环，能行）：
    ┌──────────┐
    │  LLM思考   │ ← "我需要查天气"
    └────┬─────┘
         │
    ┌────▼─────┐
    │ 调用工具   │ ← 调天气 API，拿到结果
    └────┬─────┘
         │
    ┌────▼─────┐
    │  LLM再思考 │ ← "天气知道了，现在规划行程"
    └────┬─────┘
         │
    ┌────▼─────┐
    │ 返回结果   │
    └──────────┘
```

## ③ 咱们的项目 vs LangChain

| 对比 | 咱们手写的 | LangChain |
|:---|:---|:---|
| 代码量 | ~300 行 | ~20 行 |
| 理解深度 | ✅ 每一行都懂 | ❌ 黑盒，出 bug 难排查 |
| 灵活性 | 想怎么改怎么改 | 被框架限制 |
| 适合场景 | **学习理解** | **快速开发** |

### 实际跑通验证 ✅

用 `langchain_demo.py` 实际跑了一遍 LangChain RAG 流程：

```text
切分：39 个片段 ✅
Embedding 模型加载 ✅（离线缓存）
FAISS 索引：39 个向量 ✅
检索：拿到 3 个最相关片段 ✅
LLM 调用：401 Invalid token ❌（API Key 过期）
```

**结论：** LangChain 把切分/Embedding/FAISS 封装成了几行代码。但因为咱先手写了一遍 `rag_engine.py`，所以看 LangChain 的代码能一眼看懂它在封装什么，不吃亏。

### 踩坑记录 🕳️

**问题 1：`from langchain.text_splitter import` 找不到**
- 新版 LangChain v1.3 把 text_splitter 拆成独立包了
- 解决：用 `from langchain_text_splitters import MarkdownHeaderTextSplitter`

**问题 2：`from langchain.chains import RetrievalQA` 找不到**
- 新版 chains 也被拆了
- 解决：不用 chains，手动 similarity_search + 组装 prompt 调 LLM

**问题 3：HuggingFaceEmbeddings 加载失败（国内网络）**
- 报错 `WinError 10061 目标计算机拒绝连接`
- 原因：新版本库会先联网检查模型更新，被墙了
- 解决：环境变量必须在 import 之前设
  ```python
  os.environ["HF_ENDPOINT"] = "https://hf-mirror.com"  # 国内镜像
  os.environ["TRANSFORMERS_OFFLINE"] = "1"               # 强制离线
  ```

## ④ LangGraph —— LangChain 进化版

### 一句话
> **把 AI 流程画成"带循环的流程图"。** LangChain 只能走直线(A→B→C→D)，LangGraph 能转圈(A→B→还要查?→A→C→D)，这是 Agent 必备的能力。

### 为啥需要它？
```
LangChain(直线):   问 → 调AI → 答完  → 完事
                   ⚠️ 只能走一次，没法"先查天气→再安排行程"

LangGraph(流程图): 问 → 调AI → 调工具 → 再调AI → 再调工具 → 答
                                          ↑               │
                                          └── 还能循环 ──┘
                   ✅ 能反复"思考→调工具→再思考"，直到办完
```

### 三个核心概念
| 概念 | 大白话 | 类比 |
|:---|:---|:---|
| **Node(节点)** | 每件事(思考、调工具、回答) | 流程图里的框 |
| **Edge(边)** | 事情之间的连线 | 箭头 |
| **State(状态)** | 节点间传来传去的"备忘录" | 笔记本，每步往里写，下步读 |

### LangChain vs LangGraph 对比

| 对比 | LangChain | LangGraph |
|:---|:---|:---|
| **能不能循环** | ❌ 不能(直线) | ✅ 能(带条件分支) |
| **适合作啥** | 简单流程(检索→回答) | Agent(反复思考+调工具) |
| **核心结构** | Chain(链条) | Graph(图) |
| **谁出的** | LangChain 公司 | 同一家公司，是升级版 |

### 啥时候用
| 场景 | 用啥 |
|:---|:---|
| RAG 问答(检索→回答) | LangChain 就够 |
| Agent(自己决定调啥工具) | LangGraph |
| 多 Agent 协作(一个查、一个写、一个审核) | LangGraph |
| "想想→做→再想想"的循环 | LangGraph |

### 跟咱们项目的关系
```
现在的 AgentEngine(直线):    问 ──→ AI答            (LangChain 思路)
未来的"全能导师"(Agent+RAG):  问 → 想 → 检索 ──┐
                               ↑              │
                               └── 还得查 ────┘
                                     │
                                     ▼
                                    答
```
现在的 Agent 模式够用。将来做"会自己决定要不要检索"的智能体，就需要 LangGraph。

# Phase 4 🟢 Agent 深入

## ① ReAct 模式 —— Agent 的核心思考循环

### 一句话
> **"想一步，做一步，看结果，再想下一步"** —— Reasoning + Acting = ReAct

### 流程
```
第1轮：AI 思考 → "我需要查资料"
       AI 行动 → 调工具拿数据
       收到结果
第2轮：AI 思考 → "信息够了，可以答了"
       AI 行动 → 输出最终答案
```

### 核心逻辑（伪代码）
```python
def agent_loop(question):
    messages = [{"role": "user", "content": question}]
    while True:
        response = llm(messages, tools=[可用工具])
        if response.is_answer():       # AI 觉得够了
            return response.answer
        tool_result = run_tool(...)    # AI 想调工具
        messages.append({"role": "tool", "content": tool_result})  # 继续循环
```

## ② 多 Agent 协作
```
单 Agent：一个 AI 做所有事 → 容易错、容量有限
多 Agent：专业分工
  主管 → 检索Agent → 分析Agent → 写作Agent → 审核Agent → 输出
```

## ③ Agent + RAG（全能导师核心）
```
普通 RAG：用户问 → 强行检索 → AI回答（不管需不需要）
Agent+RAG：用户问 → AI自己判断：
                      ├─ 需要查知识库 → 检索 → 结合回答
                      └─ 不需要检索 → 直接用自己知识答
```

## Phase 4 总结
| 知识点 | 一句话 | 跟项目关系 |
|:---|:---|:---|
| **ReAct** | 想→做→看→再想 | Agent 的基础原理 |
| **多 Agent** | 多个 AI 分工干活 | 以后复杂了再用 |
| **Agent+RAG** | AI 自己决定是否检索 | **就是你想要的"全能导师"** |

## ① ReAct 模式 —— Agent 的核心思考循环

### 一句话
> **"想一步，做一步，看结果，再想下一步"** —— ReAct = REasoning（推理）+ ACTing（行动）

### 现在的 Agent vs 真正的 Agent
```
现在的 AgentEngine（直线）：
  用户问 → AI 直接答 → 完事

真正的 ReAct Agent（循环）：
  用户问 → AI 想"我需要什么信息"
         → 调工具去拿信息
         → 看结果
         → 又想"够了，可以答了"
         → 输出最终答案
```

### 核心代码逻辑
```python
def agent_loop(question):
    messages = [{"role": "user", "content": question}]
    while True:
        response = llm(messages, tools=[可用工具列表])
        if response.is_answer():          # AI 觉得够了
            return response.answer
        tool_result = run_tool(response)   # AI 想调工具
        messages.append(...)               # 把结果放回去，继续循环
```

## ③ Agent + RAG —— 你想要的"全能导师"

### 普通 RAG（咱们现在的）
```
用户问 → 强行检索 → AI 根据检索内容回答
⚠️ 不管需不需要，都得搜一遍

```
用户问 → AI 自己判断：
         ├─ 知识库里有 → 去检索 → 结合回答

### 具体流程
```
用户问："Transformer 和 RNN 有什么区别？"
→ AI 思考："这个知识库里讲过，查一下"
→ 调工具 → 搜索知识库
→ 拿到笔记内容
→ 结合笔记 + 自己知识 → 回答

用户问："写一首关于 AI 的诗"
→ AI 思考："写诗不需要查资料"
→ 直接回答
```

### 跟咱们项目的关系
```
现在（v3.0.0）：
  RAG 模式：    强制检索 → 调 AI
  Agent 模式：  直接调 AI（不检索）
  两个分开的，要手动切换

未来（全能导师）：
  统一引擎：AI 自己决定检索不检索
  一个模式就够了，不用切换
```
